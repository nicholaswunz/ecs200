Week 2: Transforming and reshaping data, and writing tidy code

Raw data are rarely in exactly the form you need. Usually you need to keep some rows, drop some columns, calculate new variables, summarise by group or change the layout of the table. In this workshop you will learn the dplyr and tidyr functions that handle almost all of these jobs, and how to write code that other people (including future you) can read. Workshop materials are available in the GitHub repository ECS200.

TipLearning outcomes

By the end of this workshop you should be able to:

  1. Use filter(), arrange(), select(), mutate() and summarise() with group_by().
  2. Reshape data between wide and long format with pivot_longer() and pivot_wider().
  3. Chain several steps together with the pipe %>%.
  4. Write clean, consistent and well-annotated code.

Background

Five key dplyr functions (verbs) solve most data manipulation problems:

Verb What it does Example
dplyr::filter() Keeps rows that meet a condition Keep seedlings from 2004
dplyr::arrange() Reorders rows Sort from the tallest to the shortest seedling
dplyr::select() Keeps (or drops) columns by name Keep only watershed and stem_length
dplyr::mutate() Creates new columns from existing ones Total mass = leaf mass + stem mass
dplyr::summarise() Collapses many rows into a summary Mean stem length

All of them can be combined with dplyr::group_by(), which makes the next function work group by group (e.g. one mean per watershed instead of one overall mean).

All the verbs work the same way:

  • The first argument is a data frame (usually supplied by the pipe %>%).
  • The next arguments describe what to do, using column names without quotes.
  • The result is a new data frame.

Study context

We continue with the sugar maple data from Week 1. The dataset comes from the Hubbard Brook Experimental Forest in New Hampshire, USA.

The growth of sugar maples (Acer saccharum) can be stunted by soil acidification from acid rain, which washes calcium (an important nutrient) out of the soil. To test whether adding calcium helps, researchers at the Hubbard Brook Long Term Ecological Research (LTER) site recorded “general sugar maple germinant health by height, leaf area, biomass, and chlorophyll content” (Juice et al., 2006) for seedlings in an untreated watershed (Reference) and a watershed treated with calcium in 1999 (W1) (Peters et al., 2004).

  • arrange()
  • select()

dplyr::filter() keeps the rows that meet one or more conditions. For example, all seedlings from 2004 in the calcium-treated watershed (W1):

Code 
# Rows from the year 2004 AND the W1 watershed
plant_task_data_clean %>%
  dplyr::filter(year == 2004, watershed == "W1")
Note

Use two equal signs (==) to test whether something is equal. One equal sign (=) is used for setting the value of an argument.

To keep rows that match any value in a list, use %in%:

Code 
# Rows from transect R1 or transect W1-1
plant_task_data_clean %>%
  dplyr::filter(transect %in% c("R1", "W1-1"))

You can also filter by numeric thresholds or ranges:

Code 
# Stem dry mass of 0.05 g or less
plant_task_data_clean %>%
  dplyr::filter(stem_dry_mass <= 0.05)

# Stem dry mass between 0.01 and 0.02 g
plant_task_data_clean %>%
  dplyr::filter(stem_dry_mass > 0.01 & stem_dry_mass < 0.02)

dplyr::arrange() changes the order of the rows. Give it the column(s) to sort by. dplyr::desc() sorts from largest to smallest. Missing values always go at the end.

Code 
# Shortest to tallest seedling
plant_task_data_clean %>%
  dplyr::arrange(stem_length)

# Tallest to shortest seedling
plant_task_data_clean %>%
  dplyr::arrange(dplyr::desc(stem_length))

Datasets can have hundreds of columns. dplyr::select() keeps only the ones you name. A minus sign drops a column instead.

Code 
# Keep three columns
plant_task_data_clean %>%
  dplyr::select(year, watershed, stem_dry_mass)

# Keep everything except the sample number
plant_task_data_clean %>%
  dplyr::select(-sample)

dplyr::mutate() adds new columns calculated from existing ones (new columns are added at the end). Here we calculate the total dry mass of each seedling. The masses are in grams and very small, so we also convert them to milligrams (mg).

Code 
plant_task_data_clean <- plant_task_data_clean %>%
  dplyr::mutate(total_dry_mass    = leaf_dry_mass + stem_dry_mass, # total mass in grams
                total_dry_mass_mg = total_dry_mass * 1000)          # grams to milligrams

mutate() is also how you transform a variable, for example to reduce skew or to make a curved relationship straight (you will use this in Week 7):

Code 
plant_task_data_clean %>%
  dplyr::mutate(log_stem_length = log(stem_length)) %>%   # natural log
  dplyr::select(stem_length, log_stem_length)

dplyr::summarise() collapses many rows into one row of summary values. It becomes really useful with dplyr::group_by(), which gives you one row per group:

Code 
# Mean, standard deviation and sample size of total dry mass for each watershed
plant_task_data_clean %>%
  dplyr::group_by(watershed) %>%
  dplyr::summarise(mean = mean(total_dry_mass_mg),
                   sd   = sd(total_dry_mass_mg),
                   n    = dplyr::n())
# A tibble: 2 × 4
  watershed  mean    sd     n
  <fct>     <dbl> <dbl> <int>
1 Reference  84.4  43.9   179
2 W1        130.   62.2   179
NoteWhat happens with missing values?
Code 
# A small example with one missing value
na_data <- data.frame(site    = c("A", "B", "A", "B", "A", "B"),
                      species = c(3, 4, 6, 2, 4, NA))

# The mean for site B is NA
na_data %>%
  dplyr::group_by(site) %>%
  dplyr::summarise(mean = mean(species))
# A tibble: 2 × 2
  site   mean
  <chr> <dbl>
1 A      4.33
2 B     NA
Code 
# na.rm = TRUE removes the missing value before calculating
na_data %>%
  dplyr::group_by(site) %>%
  dplyr::summarise(mean = mean(species, na.rm = TRUE))
# A tibble: 2 × 2
  site   mean
  <chr> <dbl>
1 A      4.33
2 B      3

If any value is missing, the result is missing. Summary functions such as mean(), sd(), min() and max() have an na.rm = TRUE argument to remove them first.

Part 2: Reshaping data

Recall from Week 1 that tidy data have one row per observation. Field data sheets are often in wide format (e.g. one column per species or per month), while most tidyverse functions, and every statistical model, need long format.

tidyr::pivot_longer() turns wide data into long data. The column names become values in a new column (names_to) and the cell values go into another new column (values_to).

Code 
# A wide table: one column per month
wide_data <- data.frame(site = c("A", "B"),
                        jan  = c(10, 20),
                        feb  = c(15, 25))
wide_data
  site jan feb
1    A  10  15
2    B  20  25
Code 
# Long format: one row per site and month
long_data <- wide_data %>%
  tidyr::pivot_longer(cols      = jan:feb,   # the columns to stack
                      names_to  = "month",   # new column for the old column names
                      values_to = "count")   # new column for the values
long_data
# A tibble: 4 × 3
  site  month count
  <chr> <chr> <dbl>
1 A     jan      10
2 A     feb      15
3 B     jan      20
4 B     feb      25

tidyr::pivot_wider() does the opposite. It is useful for making summary tables that are easy to read in a report.

Code 
long_data %>%
  tidyr::pivot_wider(names_from  = month,  # the column whose values become new column names
                     values_from = count)  # the column whose values fill the cells
# A tibble: 2 × 3
  site    jan   feb
  <chr> <dbl> <dbl>
1 A        10    15
2 B        20    25

Part 3: Tidy code

Good coding style is like correct punctuation: you can manage without it, butitsuremakesthingseasiertoread. The most important rule is to be consistent. We follow the tidyverse style guide.

  • File names
  • Script layout
  • Names and spacing
  • Pipes and long lines
  • Package conflicts

File names should be machine readable (no spaces or special characters, lower case, words joined with _ or -) and human readable (describe what is in the file).

Code 
# Good
fit_models.R
week02_tidy_data.R
fig_stem_length.png

# Bad
fit models.R
foo.r
Final FINAL version2.R

Use commented lines with - to split your script into sections. Here is a template you can use for your own projects:

Code 
# Title
# Short description of what the script does
# Author, date

## Set up ## ------------------------------------------------------------------
# Load packages and set the working directory

## Load and clean data ## -----------------------------------------------------
# Import, quality check and transform the data

## Analysis ## ----------------------------------------------------------------
# Fit and check models

## Figures ## -----------------------------------------------------------------
# Make figures for your report

Use lower case letters, numbers and underscores (snake_case) for object names. Names should be short but meaningful.

Code 
# Good
stem_data
day_1

# Bad
StemData
x2
first_day_of_the_month_of_the_survey

Put spaces around operators (<-, =, +, ==) and after commas, but not inside brackets. Use <-, not =, to create objects.

Code 
# Good
total_mass <- leaf_mass + stem_mass
mean(x, na.rm = TRUE)

# Bad
total_mass<-leaf_mass+stem_mass
mean(x,na.rm=TRUE)

Avoid reusing the names of existing functions (mean, c, T, data), which causes confusing errors.

Put each step of a pipe on its own line, and each argument on its own line if a function call gets long. Keep lines shorter than about 80 characters.

Code 
# Good
plant_task_data_clean %>%
  dplyr::group_by(watershed) %>%
  dplyr::summarise(mean = mean(stem_length),
                   sd   = sd(stem_length))

# Bad
plant_task_data_clean %>% dplyr::group_by(watershed) %>% dplyr::summarise(mean = mean(stem_length), sd = sd(stem_length))

When you load the tidyverse, it prints a list of conflicts: functions with the same name in two packages. For example, stats::filter() and dplyr::filter() do completely different things. Writing the package name in front, dplyr::filter(), removes any doubt, which is why we do it throughout this unit.

Extra: operators and joins

Common operators used inside dplyr::filter():

Operator Meaning
== Equal to
!= Not equal to
<, <= Less than, less than or equal to
>, >= Greater than, greater than or equal to
%in% Matches any value in a list, e.g. site %in% c("A", "B")
& AND: both conditions must be true
| OR: at least one condition must be true
! NOT, e.g. !is.na(x) keeps non-missing values

Joins combine two data frames that share a “key” column, e.g. a table of plots and a separate table of plot soil properties.

  • left_join()
  • inner_join()
  • full_join()
  • bind_rows()

Keeps every row of the left (first) table and adds matching columns from the right table (NA if there is no match). This is the join you will use most often.

Code 
plots <- data.frame(plot = c(1, 2, 3), habitat = c("forest", "grassland", "forest"))
soils <- data.frame(plot = c(2, 3, 4), soil_ph = c(5.8, 6.4, 7.1))

dplyr::left_join(plots, soils, by = "plot")
  plot   habitat soil_ph
1    1    forest      NA
2    2 grassland     5.8
3    3    forest     6.4

Keeps only rows with a match in both tables.

Code 
dplyr::inner_join(plots, soils, by = "plot")
  plot   habitat soil_ph
1    2 grassland     5.8
2    3    forest     6.4

Keeps every row from both tables.

Code 
dplyr::full_join(plots, soils, by = "plot")
  plot   habitat soil_ph
1    1    forest      NA
2    2 grassland     5.8
3    3    forest     6.4
4    4      <NA>     7.1

Stacks data frames with the same columns on top of each other, e.g. data sheets from different field trips.

Code 
trip_1 <- data.frame(site = c("A", "B"), count = c(4, 7))
trip_2 <- data.frame(site = c("C"), count = c(2))

dplyr::bind_rows(trip_1, trip_2)
  site count
1    A     4
2    B     7
3    C     2
